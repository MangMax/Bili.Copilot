## What to build

切换分 P、重新加载或关闭播放器后，旧弹幕请求停止调度，迟到结果不会污染新视频或已关闭窗口。

证据：弹幕分段请求和信号量等待未传播放会话取消令牌，DisposeAsync 仅清空弹幕。底层 HTTP 通用捕获包装取消异常，分段客户端通用捕获还会重试。

来源：性能审查 F03（会话隔离）；基线为 4344ae756344f3ed6f1c11bd3216320b9143996f。行为机制已核实，实际耗时/内存收益未测。实施前复查最新分支及相关 PR，避免重复修复。

## Acceptance criteria

- [ ] 会话切换/关闭取消等待中与执行中的任务，取消后不再为旧会话启动新分片请求。
- [ ] 即使底层忽略取消并返回结果，也只允许当前存活会话发布弹幕、加载状态与计数。
- [ ] 正常取消不触发重试或错误通知；既有非取消失败行为保持兼容。
- [ ] 保留六并发上限，取消/异常下不会多释放或遗漏释放限流许可；不在本票引入滑动窗口预取。
- [ ] 覆盖视频与番剧分 P、重新加载、关闭以及连续切换场景。
- [ ] 附上本票相关验证证据与未验证项；不以静态分析冒充实机验收。
