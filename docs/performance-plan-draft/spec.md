范围：L；跨 AI、播放、首页、搜索与媒体资源，母票只承载规格和追踪，禁止整包作为一个实现 PR。
难度：高｜主要难点：异步结果生命周期和性能证据有效性｜建议模型：GPT Sol（high）或同级高推理模型；不在本次发起委派。

## Problem Statement

应用在 AI 长回复、弹幕初始化、首页首批内容和连续浏览等场景存在可从代码确认的重复工作、固定等待和生命周期缺口。用户希望改善响应并减少无用资源消耗，但当前没有同构建可比较的性能基线，不能把代码风险直接等同于已复现的卡顿或泄漏。

## Solution

按独立用户场景逐项消除已确认的等待与重复工作，为取消、切换和关闭建立明确的结果归属；对涉及缓存预算、第三方引擎与公共网络契约的优化先限时调查，再以证据决定实施。每个切片包含自身验证，不建立强制串行的全应用性能基础设施项目。

## User Stories

1. As an AI 用户, I want 长回复生成时仍能操作应用, so that 阅读和输入不受逐分片全量渲染影响。
2. As an AI 用户, I want 流式文本按正确顺序完整展示, so that 合并更新不会遗漏最后一段。
3. As an AI 用户, I want 停止生成后旧文本不再追加, so that 取消操作可靠。
4. As an AI 用户, I want 切换视频或重新生成后只显示新会话结果, so that 旧回调不会污染内容。
5. As an AI 用户, I want 最终答案保留 Markdown 格式且可完整复制, so that 优化不损失功能。
6. As a 阅读者, I want 清空和关闭内容时无需主动全堆回收, so that 局部清理不引入全局回收开销。
7. As a 观众, I want 换分 P 后旧弹幕加载终止, so that 网络不继续处理已离开的内容。
8. As a 观众, I want 关闭播放器后迟到结果不会重新写入, so that 资源生命周期可靠结束。
9. As a 观众, I want 弹幕已就绪时及时重绘, so that 不因未启用的另一个引擎而固定等待。
10. As a 观众, I want 两种弹幕引擎的暂停、样式和时间轴正确, so that 性能优化不改变播放体验。
11. As a 首页用户, I want 推荐/热门内容不等待侧栏目录, so that 无关接口变慢时仍能浏览。
12. As a 首页用户, I want 正确恢复上次分区排行, so that 并发加载不会显示错误栏目。
13. As a 搜索用户, I want 连续输入后只请求有效关键词, so that 减少无用请求和闪动。
14. As a 搜索用户, I want 中文输入法、联想提交和区域搜索继续正常工作, so that 防抖不破坏现有交互。
15. As a 阅读者, I want 大图按显示需要使用内存, so that 图片不会无谓占用资源。
16. As a 阅读者, I want 关闭图片内容后停止无用加载, so that 迟到结果不占据界面。
17. As a 列表用户, I want 快速滚动仍能正确续页, so that 合并检查不会漏掉加载。
18. As a 播放器用户, I want 快速切换全屏和小窗状态稳定, so that 旧延迟不能影响新模式。
19. As a 下载用户, I want 下载完成后按设置打开目录, so that 异步等待优化保持现有行为。
20. As a 下载用户, I want 多次下载完成后进程句柄得到释放, so that 长时间使用不积累无用资源。
21. As a 长期浏览用户, I want 缓存方案保留滚动位置和有效撤销能力, so that 内存预算不以丢失内容为代价。
22. As a 长视频观众, I want 优先看到当前位置附近弹幕, so that 全片慢分片不必成为展示前提。
23. As a 维护者, I want 先验证增量弹幕接口和 HTTP 解析收益, so that 不为猜测付出高风险重构成本。
24. As a 维护者, I want 每项优化有可复现的验证条件, so that 能分清真实收益和网络或设备波动。
25. As a 维护者, I want 既有刷新、撤销、托盘修复被尊重, so that 不重复开票或引入回归。

## Implementation Decisions

- 原始证据基线为 4344ae756344f3ed6f1c11bd3216320b9143996f。重新 fetch 后默认分支 master 仍指向该基线；本次并未把远端集成分支当成已经发布的代码。
- AI：在生成会话边界合并文本发布，使用会话代次隔离回调，确保末批提交和最终格式。保留非流式行为，不更换模型服务接口。
- Markdown：局部清理不主动 GC；默认图片加载复用专用连接和释放临时资源，按显示尺寸/DPI解码并拒绝过期加载。全局封面解码开关不在本次修复内。
- 弹幕：先修复会话取消与过期结果保护，沿服务到 HTTP/重试链保持取消语义；保留现有六并发。重绘按活动引擎就绪状态执行并合并；窗口预取另行调查。
- 首页：推荐/热门与目录独立加载，恢复特定排行保留真实数据依赖；不重复实现已在 #37 完成、PR #27 待合入的增量差异更新。
- 搜索：短时间防抖、取消旧请求和结果版本校验，正常取消不记错误，保留 IME/提交抑制。
- 滚动、窗口模式与下载分别是独立切片，不构成全局异步重构。
- 缓存预算、弹幕窗口预取与 HTTP 重复解析各自以半个工作日为调查时间箱；输出采样、方案与 ≤M 后续切片，不合入实验生产代码。
- 不修改数据库、服务端接口、认证策略或公共 CI 基建；跨出边界应另立规格。
- 全部子票可独立开始，当前没有真实硬阻塞；调查结果产生的后续实现票届时再设置依赖。发布时子票挂为本规格的 GitHub 原生子 issue；有后续依赖时使用原生 blocking 关系。
- 母票标记 ready-for-agent 与 scope:L 但仅追踪，不能把它认领为一张巨型实现任务；子票使用 ready-for-agent 与各自 scope 标签。

拟发布切片（标题、范围、难点与独立交付）：

- P01：[Perf] AI 流式回复合并显示并隔离过期会话；scope:M；难度高；难点：取消与队列回调乱序、最后一个分片提交；交付：长回复生成期间保持输入响应；停止或切换内容后旧回复不再写入，结束后完整呈现 Markdown。
- P02：[Perf] Markdown 清理不再主动触发全堆回收；scope:S；难度中；难点：控件清理后可重用及原生资源生命周期；交付：清空或关闭 Markdown 面板时释放自身内容，不主动要求整个应用执行全堆 GC。
- P03：[Perf] 切换或关闭播放器终止旧弹幕加载；scope:M；难度高；难点：请求取消被包装、重试与关闭回调竞态；交付：切换分 P、重新加载或关闭播放器后，旧弹幕请求停止调度，迟到结果不会污染新视频或已关闭窗口。
- P04：[Perf] 弹幕重绘按活动引擎就绪并合并请求；scope:M；难度高；难点：Win2D/DirectX 互斥引擎与卸载竞态；交付：活动弹幕引擎已就绪时立即安排重绘；快速设置变更只应用当前有效状态。
- P05：[Perf] 首页推荐首屏不等待分区目录；scope:M；难度中；难点：恢复分区排行时的依赖与布局重入；交付：默认推荐/热门内容与侧栏分区独立加载，分区接口缓慢或失败不拖住首屏。
- P06：[Perf] 搜索联想防抖并仅展示最新输入结果；scope:M；难度高；难点：IME、聚焦事件与迟到结果；交付：连续输入仅在短暂停顿后获取联想，旧结果不覆盖新输入，正常取消不刷错误日志。
- P07：[Perf] Markdown 图片复用连接并限制解码资源；scope:M；难度高；难点：DPI、WinRT 流能力及卸载取消；交付：含图片的 Markdown 重复打开时复用连接，按显示需求加载图片，关闭后停止无用加载。
- P08：[Perf] 合并滚动触底检查并阻止卸载后加载；scope:S；难度中；难点：队列合并与短列表自动补齐；交付：快速滚动和窗口缩放不会重复堆积触底检查，仍能可靠补齐短列表与继续分页。
- P09：[Perf] 播放器模式切换采用非阻塞状态收尾；scope:S；难度高；难点：快速连续切换导致旧延迟覆盖新状态；交付：全屏和小窗快速切换时状态稳定，延迟收尾不占用等待线程。
- P10：[Perf] 下载进程异步等待并确定性释放句柄；scope:S；难度中；难点：外部进程失败、退出码与目录打开时机；交付：等待 BBDown 下载完成时不长期占用线程池线程，成功后按设置打开目录并释放进程对象。
- P11：[Spike] 确定首页列表缓存预算与撤销兼容策略；scope:spike；难度高；难点：缓存淘汰破坏游标、滚动锚点或撤销快照；交付：产出有测量依据的首页缓存预算方案与可执行后续票，区分正常保留、数据增长和真正泄漏。
- P12：[Spike] 验证弹幕按播放位置预取的可行性；scope:spike；难度高；难点：第三方引擎增量数据接口与 seek 后一致性；交付：明确首段先展示与邻段预取能否在两种弹幕引擎上实现，并形成有边界的实现方案。
- P13：[Spike] 量化 bili-kernel 响应重复解析与复制开销；scope:spike；难度高；难点：公共错误处理契约、响应所有权与子模块边界；交付：判断 HTTP 重复解析是否值得优化，并给出兼容错误处理的最小方案与后续票。

## Testing Decisions

- 最高验收边界是用户操作→可见结果/网络动作/资源生命周期，真实 WinUI 交互与 Release 发布形态采样不可由纯单元测试替代。
- AI、弹幕和搜索的并发逻辑仅在无法直接测试现有服务边界时提取一个会话级协调模块；复用现有服务接口，不给每个字段或每层新增 mock 接缝。
- 已有先例：SponsorBlockServiceTests 用可记录 HTTP handler 验证请求与缓存行为；SponsorBlockLoadGuardTests 验证过期结果；VolumeCommitTrackerTests 验证合并后仅提交最新值。新增会话测试需覆盖完整异步输入输出，不能止于简单布尔守卫。
- 推荐兼容性复用集成分支的 RecommendListDiff 与快照行为测试；不为本规格重复实现已有差异工具。
- 受控时钟、请求完成顺序、取消和假响应保证确定性；不依赖真实账号/模型收费调用或固定睡眠。只测试对外行为，不测试私有字段、源码文本或方法调用排列。
- 每张修复票记录同构建、同素材下相关的请求数、UI 发布频率、分配量或等待开销；没有实测就标记未验证，不承诺百分比。构建、测试与 WinUI 验收分开记录。
- 不增加跨仓共享测试基建；若现有测试项目无法承载某接缝，先重新定级，不用扩大环境搭建掩盖切片范围。
