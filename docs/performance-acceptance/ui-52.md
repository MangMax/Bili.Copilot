## HTTP and image fixtures

`Http52` binds only `127.0.0.1` on an ephemeral port; manually serves HTTP/1.1 Content-Length bodies with keep-alive, recording connection ID, request ID, path, headers and timestamps. Three deterministic 24-bit BMPs contain gradient/checkerboard pixels: landscape **2400×1200 / 8,640,054 bytes**, portrait **1200×2400 / 8,640,054 bytes**, square **2000×2000 / 12,000,054 bytes**. Generator and per-run SHA-256 fixture manifests are retained. These are synthetic large bitmaps, not representative JPEG/PNG compression or EXIF cases.

SVG is a 174-byte ISO-8859-1 body with `Content-Type: image/svg+xml; charset=iso-8859-1`, teal rectangle and `<text>café</text>`. Source inspection (`rg SVGRenderer src`) finds no app injection replacing the default: `MarkdownConfig.SVGRenderer` defaults null and `MyImage` selects `DefaultSVGRenderer`. `Renderer52` and the releasable renderer delegate to that actual implementation. The separate Boundary52 also calls the actual loader charset helper and then actual DefaultSVGRenderer. It does not replace SVG rendering with a fake provider.

The `/slow` response sends headers plus 64 body bytes, then awaits a harness-controlled gate. Provider fixtures use only a packaged logo, with a cached Image or explicit TaskCompletionSource. Default bitmap/SVG cases use **real HTTP → production loader → real control/renderer**, not provider bypass. Boundary controls are separately labelled diagnostic experiments and do not validate MyImage integration.

## Production lifecycle finding

[C lifecycle log](evidence-52/boundary-c/lifecycle52.json) and [C state/HTTP log](evidence-52/boundary-c/image52.json) provide a concrete reproduction. One click of Next52 on a newly mounted Markdown control with the landscape HTTP URL is enough:

1. Inline host **31763454** receives Loaded at `18:37:15.086Z` with `IsLoaded=false` (two recorded callbacks).
2. At `18:37:15.198Z` it has child **58199431**, `Source=BitmapImage`, `IsLoaded=true`.
3. At `18:37:15.200Z`, Unloaded callbacks run while the **same host still reports IsLoaded=true**; its child identities change to **29639035**, then **49763145**, both null Source. A further Unloaded at `18:37:15.229Z` leaves child **53667499** null.
4. At `18:37:22.918Z`, the Markdown is loaded with one block, but the visual image has zero width/height and null Source. Two complete landscape HTTP responses were served on connection 1. The screenshot is blank and the bounded eight-second readiness check fails.

Production `MyImage.OnUnloaded` unconditionally cancels and replaces its image; `IsCurrent` requires `_host.IsLoaded`. The public trace shows those lifecycle assumptions are unsafe for this real inline host. Initial synchronous provider publication is also rejected/absent in the tested cases. This is a **reproducible production integration failure**, not proof that the codec failed or that historical #46/#47 evidence had the same cause. Exact WinUI event origin/reparenting causality was not fully isolated; no source fix or private-field mutation was attempted. B's first-chance log contains cancellation exceptions, not an independently diagnosed codec failure.
