## Blocking production defect, reproducible from a fresh process

**AppSearchBox's unload cleanup stops executing after its first unload.** The real dependency's `LayoutUserControlBase.OnUnloaded` removes both its Loaded and Unloaded subscriptions before calling the virtual OnControlUnloaded. It never reattaches them. AppSearchBox depends exclusively on that virtual override for cancellation, collection cleanup and interaction-version invalidation.

Read-only disassembly of the cached production dependency using already installed Mono.Cecil is preserved in [base-lifecycle-il.txt](evidence-51/base-lifecycle-il.txt): `remove_Loaded` at IL_000d, `remove_Unloaded` at IL_001f, virtual cleanup at IL_0066. This is not a substituted test base. Parent fix should account for repeated real Unloaded events without changing the kernel gitlink as part of this acceptance task.

Small reproduction: [repro-unload.ps1](harness-51/repro-unload.ps1), fresh process 63892, actual [results](evidence-51/repro-01/results.json) **1 PASS / 2 FAIL**, assertions intentionally retained:

1. Focus empty search; hold recommendation request. Detach, complete cancelled recommendation, reattach same instance. `FirstUnloadCancelsFocusRequest` passes.
2. Focus again, switch this input to English, type `q`. Detach within the 250ms debounce. `SecondUnloadCancelsDebounce` fails: a request starts while IsLoaded=false.
3. Complete that request while still detached. `SecondUnloadRejectsLateResponse` fails: `q result` is published to Suggestion while IsLoaded=false.
4. Reattach: the stale collection remains. **The popup was closed in this reproduction; a late popup reopening is not claimed.**
