# 节点选择与播放器刷新：短设计

状态：用户已确认并授权实施（2026-11-07）。

## 用户已确定的行为

- 增加节点选择能力，默认策略参考 BiliPai。
- 播放器界面只提供刷新按钮，不增加节点选择面板。
- 点击刷新后自动重新连接并继续播放。
- 使用现有 mpv，不依赖 ExoPlayer，不接管分段下载。

## 建议方案

设置 → 播放 → 播放线路：自动（默认）／原始主线路／备用线路／服务商偏好（阿里、腾讯、华为、海外）。服务商偏好只匹配当前媒体 API 返回的候选；没有匹配项时回退自动。选项文案明确“优先”，不暗示该服务商一定可用。仅存偏好，不保存带签名的播放 URL。

播放器控制栏只增加一个“刷新播放”图标按钮，提供 Tooltip 和无障碍名称，正在刷新时禁用重复触发。不增加测速图表或节点菜单。

默认自动策略借鉴 BiliPai 的安全候选路径：主地址＋备用地址去重，优先低风险 CDN，降低已知 P2P/边缘地址优先级；同级无证据时保持稳定顺序。第一版不做后台测速、持久化健康评分或随机换线，不声称完整移植其智能下载系统。

BiliPai 参考版本 20017b1ac48f7792e744259551a5a54258a81896：CdnOptimizationPolicy 的安全排序包含固定 host 偏好、风险分类、健康分数；风险名单包含 mountaintoys.cn。本项目应使用规范化 host 和严格域名边界匹配，不能把任意 contains 命中当权威 P2P 证明。已知风险分类用于偏好，不推导本次网络错误责任。

已有“不使用 P2P”设置保留，作为选择前的过滤偏好；先遵守过滤再应用线路偏好。保持当前“没有非 P2P 候选时允许回退”的兼容行为并明确文案，不在本次悄悄改成播放失败。此开关与节点偏好不是两个互相覆盖的独立选择器。

## 刷新行为

1. 捕获当前媒体/分 P/剧集及会话代次、进度、所选清晰度与编码偏好、倍速、音量/静音、暂停状态。
2. 使解析器播放信息缓存失效并真正重新请求 playurl；不能只重复调用缓存中的 GetSourceAsync。
3. 根据设置重新选择地址。自动模式下有同级合适替代 host 时本次优先换一个；只有一个可用 host 时同源重开。固定服务商优先在该服务商内换线，无候选则按设置回退自动。手动刷新本身不永久判罚旧节点。
4. 重新加载媒体并从当前位置继续，而非只执行 seek；保持画质/倍速/音量及暂停意图。最新用户操作优先，刷新不能覆盖期间发生的 seek、暂停、换集或关闭。
5. 单次刷新是有界操作，不做无限重试。获取新地址失败时尽量保留原播放；加载失败使用现有错误提示。可能短暂停顿，不保证无感。

范围包括普通视频和 PGC 分轨点播；直播、本地文件和外部播放器不套用此按钮与候选策略。

## 改动边界与任务图

### 模块组织（参考现有空降助手）

采用应用内独立功能模块，不新建插件系统或单独程序集。现有 SponsorBlock 的做法是独立目录承载策略/控制器，再由 PlayerViewModel.SponsorBlock.cs 接入；本功能沿用同类组织。

- `PlaybackRouting/`：集中放候选地址、线路偏好、风险分类、排序与刷新控制流程。策略不依赖 WinUI 或 mpv；控制流程通过窄适配调用真实媒体源获取和重开，不直接持有页面控件。
- `PlayerViewModel.PlaybackRouting.cs`：只承接刷新命令、状态通知及生命周期接入，并适配现有会话有效性、seek/调速串行化与播放器重开能力。模块复用现有会话标识，不另造独立播放器生命周期。
- 普通视频/PGC 解析器继续负责各自媒体信息与鉴权，调用同一候选选择策略，并提供明确的强制刷新入口。刷新控制器不复制两套 playurl 请求或质量选择规则。
- 设置控件/设置视图模型单独组织线路设置；播放器控制栏只绑定一个刷新命令和刷新中状态。
- 测试通过模块对外行为覆盖选择、回退、取消和过期结果；少量集成测试验证解析器与真实播放器适配。只拆真正具有独立职责的类型，不预先创建每个动作一个类。

这是“独立模块＋现有模块少量接线”，不可能完全零修改播放器/解析器；不会把所有逻辑藏到一个 partial 文件里后称作模块化。

整体为 L 级协调范围（设置、两个解析器、播放器命令/UI、异步会话约束），不在一个未拆分工单里同时开展。

1. **节点选择设置与点播候选策略（M）**：无阻塞。设置保存偏好，普通视频和 PGC 加载都使用同一策略；验证主/备、服务商缺失回退、P2P 偏好与独立音轨。
2. **刷新按钮与保留状态的重连（M）**：被 1 阻塞。实现 playurl 真刷新、节点重选、原位重开与会话隔离；播放器只出现一个刷新按钮。

沿用当前 integration/spec-182-playback-freeze 集成分支和草稿 PR #185。规格 #182 与修复票 #184 应明确调整为“节点选择与用户触发恢复”，不再以“自动识别/彻底修复所有永久冻结”作为交付声明。调查 #183 保持已完成。

## 测试边界

- 最高现有边界为媒体源解析结果与播放器公开刷新行为，优先扩展已有测试适配，避免为私有方法逐个写测试。
- 候选选中结果、签名 URL 不被改写、缺少备用/匹配服务商、视频/音频独立选择、风险域名边界、既有 P2P 设置兼容。
- 刷新确实重新调用 playurl 服务并重载，不复用旧缓存；旧请求延迟完成不得回写新一代媒体状态。
- 连续点击、刷新期间 seek/暂停/倍速变化、换集、关闭、请求与加载失败均有行为验证。
- 真实 libmpv：模拟坏缓存之后点击等价刷新动作，记录新的 Range 请求和恢复后的解码帧；这不能替代 WinUI 按钮与状态验收。
- 受影响 .NET 测试、项目构建/WinUI analyzer 与可运行环境中的原生 UI 验收。
