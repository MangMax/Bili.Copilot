# 联合投稿头像名称列表

视频播放页的信息区在多人投稿时，原本把主投稿人与合作者姓名拼成一段文字（`A、B、C`）。本轮改为：上方保留主投稿人的头像与关注操作，下方新增一个头像名称列表展示合作者，点击条目进入对应用户空间。适用范围仅限 UGC 视频播放页信息区，不改动视频卡片与 PGC/番剧页面。

## 布局与视觉

- 列表位于 UP 主区域与统计行之间，与作者区共用同一条左缘：区块不设外边距，标题、头像各内缩 4 DIP，和上方 UP 主头像、下方信息的对齐节奏一致；上方作者区仍使用现有控件与负边距。
- 标题复用现有「联合投稿」文案，采用 Caption 层级与三级文字色，与首行间隔 6 DIP；没有合作者时整个区块折叠，单人投稿的显示与改动前一致。
- 每个条目是与作者区同构的整行人员条目：32 DIP 圆形头像，右侧名称 13 DIP SemiBold、角色用 Caption 层级三级色放在名称下方；名称单行截断，整行占满侧栏宽度，行间距 2 DIP。
- 条目内边距 4 DIP，悬停沿用原生按钮浅底与 4 DIP 圆角；点击任意位置进入用户空间。没有角色时第二行隐藏，名称仍与头像垂直居中。
- 角色（如「剪辑」「参演」）作为可见文本展示，不再依赖悬浮提示；完整姓名仍作为截断时的提示。

## 数据与状态

- 数据来自内核 `VideoInformation.Collaborators`；`CollaboratorListBuilder` 按接口顺序去重（以用户 Id 为准）、排除无名称条目与主投稿人。
- 主投稿人不出现在列表里，避免与上方 UP 主区域重复；`UpName` 只显示主投稿人姓名，主投稿人资料缺失时才退回原来的姓名拼接。
- 条目点击使用合作者自带的 `UserProfile` 打开用户空间，资料不全时由用户空间页面按 Id 补全。
- 切换视频时清空列表与可见性；列表为空时区块不占位。

## 可访问性与测试

- 头像条目提供用户名的自动化名称、以用户 Id 作为自动化 Id；角色作为正文旁的可见文本，辅助技术可直接读取；标题使用现有本地化字符串，不新增资源项。
- `CollaboratorListBuilder` 的排除主投稿人、去重、忽略空名称、保留角色与顺序行为由 `CollaboratorListBuilderTests` 覆盖。
- UI 工程按默认阻断口径构建（WinUI 分析器 warning 为 0）。
