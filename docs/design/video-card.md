# 网格视频卡片

推荐、热门、排行榜、分区、全站视频搜索、UP 主空间视频搜索、稍后再看和普通视频收藏共用 `FeedVideoCardStyle`。历史、动态、番剧和播放器侧栏继续使用各自的专用模板。不同入口保留原有 `VideoCardStyle` 和命令，不复制卡片业务逻辑。

## 布局与交互

- 封面比例 16:10，封面圆角 8，卡片内边距 8，外层圆角 16，满足外圆角等于内圆角加内边距。
- 标题最多两行。40 DIP 头像与右侧两行资料整体居中；第一行是姓名及其前方的已关注标记，第二行是推荐理由、分区、时间和更多操作。
- 推荐理由采用强调色，分区采用带图标的黑色胶囊。无标签时，时间放在标签位置；稍后再看和收藏显示收集时间，其余入口显示发布时间或服务端的时间描述。
- 联合投稿与充电专属是封面左上的纯文字角标，高 20、圆角 4、左右内边距 6，距封面左 10、上 8。联合投稿背景为 `#990A0C10`，充电专属为 `#CC0C4470`。联合投稿作者显示“第一作者 等 N 人”。
- 头像和姓名打开主作者空间；普通用户的提示不预留认证、会员空行。更多按钮与右键菜单复用真实命令，不支持固定或置顶。
- `InlineTextButton` 统一可点击文字的悬停背景间距，保留原生按钮的命令、焦点和自动化语义。

各页面分别持有自己的原生 `UniformGridLayout`，不共享有状态布局实例，不指定随宽度失效的固定行高。`PopularVideoCardPanel` 测量封面与完整正文；排列时先保留正文高度，再把剩余高度分配给封面，避免 DPI 取整造成底部裁切。`PopularVideoLabelsPanel` 负责有限空间内的标签优先级及宽度取整，不负责网络或业务状态。

## 数据与职责

控件的业务输入仍只有 `VideoItemViewModel`。ViewModel 使用普通数据和可观察属性；画笔、可见性及模板留在视图层。模板中的运行时绑定使用带 `GeneratedBindableCustomProperty` 的来源，动态派生属性具备变更通知。

`VideoCardMetadataProvider` 缓存公开元数据、合并同一视频的请求并限制四个并发请求。它通过内核 `IPlayerService.GetVideoInformationAsync` 读取 Web 视频详情，不请求播放进度或互动状态。刷新得到的条目能复用已知头像；一个卡片卸载只取消自身等待，不取消其他卡片共享的请求。完成通知发生在共享请求槽位清理之后，失败可以立即重试。

`UserRelationBatcher` 按当前账号批量读取作者关系，区分已关注、未关注和未知；账号切换丢弃旧响应，失败保留最近成功状态。`PublisherFollowingState` 保存单卡仍有效的最近成功结果，避免缓存淘汰或重新挂载把已确认状态清空。界面只把明确的已关注显示为标记。

内核负责响应适配与鉴权：

- 优先使用列表已提供的头像、时间、分区和关注状态，详情补全缺失字段与内容分类。
- 合作标志来自 `rights.is_cooperation`，创作者来自 `staff`；显示人数按 UID 对主作者和参与者去重，不解析标题。
- 充电分类来自 `is_upower_exclusive`，不与 `is_upower_play` 或 `is_upower_preview` 混用，也不据此推断当前用户禁止播放。
- 单查与批查复用关系状态映射，保留特别关注；未知字段不当作明确未关注。
- 稍后再看 Web 列表使用 Cookie/WBI，禁止 App access token。公开页号从 0 开始，内核转换为 Web 的 1 起始页号；错误或缺失数据抛出异常，不伪装为空列表。

认证和会员头像角标已按需求舍弃，未保留无产品消费者的相关字段和资源。

## 验证

纯内核 HTTP/gRPC 契约测试位于内核已有的 `BiliKernel.Tests` 项目；卡片缓存、账号状态和并发测试位于 `BiliCopilot.PopularCard.Tests`；稍后再看页面失败、空列表和重试测试位于 `BiliCopilot.UI.Tests`。应用 CI 同时执行这三个层次的测试，WinUI 分析器继续使用仓库默认阻断规则。
